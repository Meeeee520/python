## 1. 本地保存、commit、push 是三件事

| 动作 | 主要作用 |
| --- | --- |
| 保存文件 | 改变当前工作区 |
| `git add`、`git commit` | 选择并记录本地版本 |
| `git remote -v` | 查看已配置远程的地址，不会上传 |
| `git push origin main` | 尝试将本地 main 的提交更新到 origin 的 main |
| `git pull --ff-only origin main` | 获取远程更新，并只允许可快进的整合 |

`origin` 只是常用的远程别名，不是 GitHub 密码，也不保证一定指向你自己的仓库。`main` 是这里使用的分支名；真实项目应先核对实际分支。

今天先在新的练习目录完成项目资料；本文不会替你创建 GitHub 仓库、登录、公开文件或向任何真实远程推送。下面的 GitHub 地址是占位符，不能原样执行。

若你之后选择使用自己新建、无个人资料的私有练习仓库，确认权限和地址后才手动配置：

```bash
git remote -v
# 仅在 origin 尚不存在、已确认本人练习仓库地址时执行：
git remote add origin "https://github.com/YOUR_ACCOUNT/YOUR_PRACTICE_REPO.git"
```

已有 origin 时先检查，不直接覆盖其地址。身份验证按 GitHub 正常登录流程操作，不把密码或令牌写进 URL、README 或代码。

## 2. 推送前检查，拉取失败先停

只对已确认的练习仓库手动执行：

```bash
git status --short
git diff --cached --name-only
git ls-files
git remote -v
```

确认无私人文件、目标正确、所需修改已经提交后，才考虑 `git push -u origin main`。`-u` 设置分支跟踪关系，不等于绕过权限。

在干净的练习工作区里更新已有本地分支，可使用：

```bash
git pull --ff-only origin main
```

`--ff-only` 在分支已分叉时会拒绝整合，不替你生成合并提交，也不抛弃本地提交。若提示非快进或分支分叉，先保留现场、阅读状态，不用强推或删除历史来“解决”。有未提交修改时也先处理并确认，不把 pull 当作任意覆盖本地的按钮。

## 3. README 要让别人不靠猜

最小项目说明应包括用途、运行环境、文件名、运行命令、正常样例和边界行为。下面内容保存到练习项目的 `README.md`：

```markdown
# Score Report

用途：读取一行整数成绩，输出记录数与两位小数平均分。
环境：Python 3；只使用标准库，不需要安装第三方包。
文件：score_report.py
运行：python3 score_report.py
输入约定：一行 0–100 的整数字符串，用空格分隔；空行表示无记录。
正常输入：60 80 100
正常输出：Count: 3，然后 Average: 80.00（各一行）。
空行输出：Count: 0，然后 Average: N/A（各一行）。
单个 0 是一条合法成绩，不是空输入。
本练习不读取或上传个人成绩文件。
```

## 4. 沿用能运行的 Python 程序

保存为 `score_report.py`。这是昨天报告逻辑的复用；今天重点是交接和同步，不为写文档另造复杂程序。输入按 README 中的约定提供。

```python
def report(scores):
    if not scores:
        return "Count: 0\nAverage: N/A"
    return f"Count: {len(scores)}\nAverage: {sum(scores) / len(scores):.2f}"


def main():
    scores = [int(part) for part in input().split()]
    print(report(scores))


if __name__ == "__main__":
    main()
```

运行 `python3 score_report.py`，输入 `60 80 100`：

```text
Count: 3
Average: 80.00
```

空行输出：

```text
Count: 0
Average: N/A
```

单个 `0` 应输出数量 1、平均分 0.00。README 中的所有样例必须与真实程序一致。

## 5. 忽略缓存，但别误以为忽略规则能抹掉历史

在新练习目录创建 `.gitignore`：

```gitignore
__pycache__/
*.pyc
scores.csv
.env
```

这些规则用于忽略未跟踪的缓存或数据文件；不会删除磁盘文件，也不会自动取消已跟踪的文件。若私人文件已经进入暂存区或提交历史，先停止推送并检查，不因为加了规则就认为资料已经安全。

在全新练习仓库只暂存这三份教学文件：

```bash
git add .gitignore README.md score_report.py
git diff --cached --name-only
```

预期清单：

```text
.gitignore
README.md
score_report.py
```

若出现其他文件，先检查来源，不用批量暂存或删除来追求“干净”。第五题提供未跟踪与已经跟踪两种情境的只读自检；练习中的数据均为虚构测试文件，不能换成个人资料。

## ⚠️ 易错点

| 误解 | 正确理解 |
| --- | --- |
| commit 后 GitHub 一定更新了 | 本地提交与远程推送不同 |
| origin 一定是自己的仓库 | 它只是别名，必须检查实际地址 |
| README 写个“运行即可”就够 | 要给环境、命令、输入输出与边界 |
| `.gitignore` 会取消已跟踪文件或清除历史 | 它主要影响未跟踪文件；不能当作隐私补救 |
| 推送拒绝就应该强推 | 先检查远程更新、权限和分支关系，不覆盖他人或本地历史 |

### 练习 1：看方向

`push` 和 `pull` 的方向有什么不同？

<details><summary>查看答案</summary>

push 尝试将本地提交更新到远程；pull 获取远程更新并按指定策略整合到当前本地分支。它们不等同于保存文件。
