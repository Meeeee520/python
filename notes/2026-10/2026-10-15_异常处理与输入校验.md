## 🎯 今日目标

- 区分语法错误与程序运行时出现的异常。
- 知道 `int()` 无法转换非整数字符串时会抛出 `ValueError`。
- 会用 `try` / `except ValueError` 只保护可能失败的转换语句。
- 理解“能转成整数”和“数值在允许范围内”是两种不同检查。
- 会用 `while True`、`continue` 和 `return` 重试输入。
- 不用宽泛的 `except Exception` 掩盖真正的程序错误。

## 1. 异常不是语法错误

下面代码少了冒号，程序还没开始运行就无法解析，这是 `SyntaxError`：

```python
if score >= 60
    print("Pass")
```

而下面代码语法正确，但输入 `cat` 时，`int("cat")` 无法完成转换，会在运行时抛出 `ValueError`：

```python
score = int(input())
```

异常处理针对的是**可以预料的运行时失败**。它不能把拼错变量名、逻辑写反或漏冒号自动修好。

## 2. 只捕获你真正能处理的异常

```python
text = "cat"

try:
    score = int(text)
except ValueError:
    print("Not an integer")
else:
    print("Score:", score)
```

输出：

```text
Not an integer
```

执行顺序是：

1. 先执行 `try` 中的转换。
2. 如果抛出 `ValueError`，跳到对应的 `except`。
3. 如果没有异常，跳过 `except`，执行 `else`。

`try` 中只放 `int(text)` 这类可能失败、而且你知道怎样处理的代码。范围判断和后续统计放在外面，更不容易误把别处的错误也捕获掉。

## 3. 转换成功，不代表数据有效

```python
text = "105"
score = int(text)
print(score)
```

`105` 可以成功转换成整数，因此不会抛出 `ValueError`；但如果成绩必须在 0 到 100 之间，它仍然是无效输入。

所以输入校验通常分两层：

- **格式校验**：能不能转换成整数？失败时处理 `ValueError`。
- **业务范围校验**：整数是否满足 `0 <= score <= 100`？用普通 `if` 判断。

异常不是所有错误的代名词；范围不合要求通常只是一个需要重新输入的分支。

## 4. 先写成纯函数，更容易测试

```python
def parse_score(text):
    text = text.strip()
    if not text:
        return None, "Empty input"

    try:
        score = int(text)
    except ValueError:
        return None, "Not an integer"

    if not 0 <= score <= 100:
        return None, "Out of range"

    return score, "OK"
```

```python
for raw in ["86", "cat", "105", "   "]:
    value, message = parse_score(raw)
    print(value, message)
```

输出：

```text
86 OK
None Not an integer
None Out of range
None Empty input
```

这个函数不直接读取键盘，所以能用固定字符串反复测试正常与边界情况。

## 5. 用循环让用户重新输入

```python
def read_score():
    while True:
        value, message = parse_score(input())
        if value is not None:
            return value
        print("Invalid:", message)


score = read_score()
print("Accepted:", score)
```

如果依次输入 `cat`、`105`、`86`，输出为：

```text
Invalid: Not an integer
Invalid: Out of range
Accepted: 86
```

`return` 会同时结束函数和 `while True`。无效输入则打印原因，循环自然进入下一轮。

## 6. 为什么不直接写 `except Exception`

```python
try:
    score = int(text)
except Exception:
    print("Invalid")
```

这段代码可能把本应暴露的程序错误也吞掉，让你误以为都是用户输入问题。已知 `int()` 的预期失败是 `ValueError`，就精确捕获它：

```python
except ValueError:
```

原则是：**只捕获你预料到、并且真的能处理的异常。**

## ⚠️ 易错点辨析

| 常见误解 | 正确理解 | 修正 |
| --- | --- | --- |
| `try` 能修复语法错误 | 语法错误发生在程序运行前 | 先根据报错位置修正代码 |
| `int("86.5")` 会得到 86 | 带小数点的字符串不能直接转成 `int` | 依据需求使用 `float` 或拒绝输入 |
| 转换成功就一定有效 | `105` 是整数，但可能超出成绩范围 | 转换后继续做范围判断 |
| `except Exception` 最省事 | 它可能掩盖真正的程序错误 | 捕获具体的 `ValueError` |
| 把整个程序都放进 `try` | 会让异常来源难以判断 | `try` 只包围最可能失败的最少代码 |
| 无效输入后直接结束 | 用户没有机会修正 | 在循环中提示并重试 |

### 练习 3 · 完成解析函数

实现 `parse_score(text)`：空白返回 `(None, "Empty input")`，非整数返回 `(None, "Not an integer")`，越界返回 `(None, "Out of range")`，合法时返回 `(score, "OK")`。

```python
def parse_score(text):
    text = text.strip()
    if not text:

    try:

    except ValueError:
```
