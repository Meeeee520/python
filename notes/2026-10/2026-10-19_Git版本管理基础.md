## 1. 三个位置，分别放什么

可以把 Git 想成给代码拍照：工作区是你正在整理的桌面，暂存区是你挑选好的拍摄内容，提交历史是已经存下来的照片。

| 位置 | 含义 | 常用动作 |
| --- | --- | --- |
| 工作区 | 目前磁盘里保存的文件 | 用编辑器修改并保存 |
| 暂存区（index） | 准备进入下一次普通提交的文件版本 | `git add report.py` |
| 本地历史 | 已创建的提交快照 | `git commit -m "说明"`，再用 `git log` 查看 |

`git add` 不是持续同步开关。例如先保存版本 A，再 `git add report.py`，然后保存版本 B：暂存区仍是 A。要把 B 放进下一次提交，需要再次 `git add report.py`。

今天只练本地 Git。**本地 `commit` 不会自动上传到 GitHub**，也不要求执行 `push`。不要把自己的网站、个人账本、答案或现有公开仓库拿来试验。

## 2. 先看清楚，再提交

| 命令 | 回答的问题 |
| --- | --- |
| `git status --short` | 哪些文件未跟踪、已修改或已暂存？ |
| `git diff -- report.py` | 工作区相对暂存区，还有哪些未暂存的改动？ |
| `git diff --cached -- report.py` | 暂存区相对最近提交，准备提交哪些改动？ |
| `git add report.py` | 把这个文件当前保存的内容放进暂存区 |
| `git commit -m "fix: handle empty scores"` | 将已暂存内容记录为一次本地提交 |
| `git log --oneline -3` | 查看最近三次提交及其简短说明 |

`--cached` 和 `--staged` 在这里含义相同。普通 `git diff` 没输出，只能说明没有这一类未暂存的已跟踪文件差异，不能据此断言完全没有改动；还要检查暂存区以及未跟踪文件。

## 3. 短状态的两个字母

非合并冲突场景下，第一列描述暂存区相对最近提交的状态，第二列描述工作区相对暂存区的状态。

| 输出 | 含义 |
| --- | --- |
| `?? report.py` | 新文件，尚未跟踪 |
| `A  report.py` | 新文件已暂存，工作区和暂存区一致 |
| ` M report.py` | 已跟踪文件被修改，但没有暂存这一改动 |
| `M  report.py` | 修改已暂存，工作区和暂存区一致 |
| `MM report.py` | 修改已暂存，之后又有新的未暂存修改 |

表格里的空格有意义。今天的输出题使用 `MM`，避免把空格数量当成主要考点。新文件暂存后又修改可能显示 `AM`，因此不能看到两个状态就一律背成 `MM`。

## 4. 可运行的 Python 最终版本

在**新建的空练习目录**保存为 `report.py`。输入约定：一行合法整数成绩，空行表示没有成绩；今天不重新扩展输入校验功能。

```python
def report(scores):
    if not scores:
        return "Count: 0\nAverage: N/A"
    return f"Count: {len(scores)}\nAverage: {sum(scores) / len(scores):.2f}"


def main():
    scores = [int(part) for part in input().split()]
    print(report(scores))


if __name__ == "__main__":
    main()
```

运行 `python3 report.py`，输入 `60 80 100`：

```text
Count: 3
Average: 80.00
```

空行时输出：

```text
Count: 0
Average: N/A
```

单个 `0` 的输出必须是 `Count: 1` 和 `Average: 0.00`，与空输入不同。

## 5. 小项目：留下三个有意义的版本

在一个全新的练习文件夹中执行以下终端命令。**不要在原学习网站目录或现有仓库中初始化练习。**

```bash
git init
git status --short
```

若 Git 尚无提交身份，可以只在这个练习仓库配置虚构的训练身份；它不用于公开提交，也不修改全局设置：

```bash
git config user.name "Practice Learner"
git config user.email "practice@example.invalid"
```

按[项目手册](../../projects/2026-10/daily-2026-10-19.md)中的三个版本依次编辑、运行和提交：

1. 版本 1：只输出数量，提交 `feat: count scores`。
2. 版本 2：增加非空成绩平均分，提交 `feat: add average`。
3. 版本 3：补上空输入处理，提交 `fix: handle empty scores`。

每一轮都先保存文件，再执行：

```bash
python3 report.py
git diff -- report.py
git add report.py
git diff --cached -- report.py
```

确认暂存内容符合本轮目标后，执行对应的 `git commit -m "..."`。最后查看：

```bash
git log -3 --format=%s
git status --short
```

最后三条提交说明应由新到旧显示：

```text
fix: handle empty scores
feat: add average
feat: count scores
```

在只有这些已提交练习文件、没有其他改动的目录中，最后的短状态无输出。提交 SHA 会变化，不要求背下或与示例相同。今天不练删除历史或丢弃修改的命令。

## ⚠️ 易错点

| 误解 | 正确理解 |
| --- | --- |
| 保存文件就进入历史了 | 保存只改变工作区；还需要暂存和提交 |
| `git add` 后继续编辑，下一次提交会自动带上新修改 | 普通提交使用已暂存的版本；新修改需要重新暂存 |
| `git diff` 空白就说明工作区完全干净 | 还要检查暂存差异与未跟踪文件 |
| 用 `git add .` 一次全交最省事 | 入门时按文件暂存，避免把无关数据或私人文件放进去 |
| `commit` 等于上传 GitHub | 它只创建本地提交；远程同步明天再学 |
| 能提交就代表程序正确 | Git 记录版本，不替你运行或证明测试 |

记录 A；B 仍是工作区里尚未暂存的新修改。要提交 B，应再次暂存这个文件，并检查暂存差异。

</details>

### 任务 2：选择正确的比较

准备确认下一次提交中 `report.py` 的变化，应查看哪条命令？

<details><summary>查看答案</summary>

`git diff --cached -- report.py`。它比较暂存区与最近提交；普通 `git diff -- report.py` 比较工作区与暂存区。

</details>

### 任务 3：保留小检查

在同目录另开 Python，导入函数后检查正常、空和 0 分边界：

<details><summary>查看可运行检查</summary>

```python
from report import report

assert report([60, 80, 100]) == "Count: 3\nAverage: 80.00"
assert report([]) == "Count: 0\nAverage: N/A"
assert report([0]) == "Count: 1\nAverage: 0.00"
```

导入时不应触发输入。导入可能生成 `__pycache__` 缓存；若状态显示这个未跟踪目录，先不要暂存，不要为了让状态干净就把缓存提交。忽略规则留到明天，已跟踪源文件的提交情况仍可单独检查。今日第五题另用一个独立练习仓库检查“只提交指定文件”，不要求在个人仓库中操作。

</details>
