## 1. 模块就是可导入的 Python 文件

建立 `stats.py`：

```python
def average(scores):
    if not scores:
        return None
    return sum(scores) / len(scores)
```

在同一目录的 `app.py` 中导入：

```python
import stats

print(stats.average([60, 80, 100]))
```

输出：

```text
80.0
```

`import stats` 会创建模块名 `stats`；模块里的函数通过 `stats.average` 访问。保留模块名前缀，能清楚看出函数来自哪里。

## 2. 导入时也会执行顶层语句

如果 `stats.py` 写成：

```python
def average(scores):
    return sum(scores) / len(scores)

print(average([10, 20]))
```

执行 `import stats` 时，最后一行也会运行并打印 `15.0`。函数定义适合复用，但交互输入和演示输出通常不应该在导入时自动执行。

## 3. 用 `__main__` 保护程序入口

```python
def average(scores):
    if not scores:
        return None
    return sum(scores) / len(scores)


def main():
    scores = [60, 80, 100]
    print(average(scores))


if __name__ == "__main__":
    main()
```

- 直接运行 `python3 stats.py` 时，`__name__` 是 `"__main__"`，会调用 `main()`。
- 在别的文件中 `import stats` 时，`__name__` 是 `"stats"`，不会自动调用 `main()`。

这样既能直接运行，也能安全导入并测试函数。

## 4. 把输入输出与计算分开

```python
def summarize(scores):
    if not scores:
        return {"count": 0, "average": None}
    return {
        "count": len(scores),
        "average": sum(scores) / len(scores),
    }


def main():
    scores = [int(part) for part in input().split()]
    result = summarize(scores)
    print(result)


if __name__ == "__main__":
    main()
```

`summarize` 不读取键盘，也不打印，因此可以直接测试：

```python
print(summarize([]))
print(summarize([60, 80, 100]))
```

输出：

```text
{'count': 0, 'average': None}
{'count': 3, 'average': 80.0}
```

## 5. 怎样读 traceback

下面函数忘记处理空列表：

```python
def average(scores):
    return sum(scores) / len(scores)


print(average([]))
```

异常最后一行类似：

```text
ZeroDivisionError: division by zero
```

调试顺序：

1. **先看最后一行**：异常类型和消息是什么？
2. **向上找自己写的最内层行号**：哪一行真正失败？
3. **检查当时的数据**：`scores` 为什么是空列表？
4. **做最小修复**：在计算前处理空列表。
5. **重新运行正常与边界输入**：不能只确认异常消失。

不要一看到错误就加 `except Exception`。如果代码逻辑本来就有漏洞，吞掉异常只会让错误更难发现。

## 6. 调试不是“盯着代码猜”

最小复现可以缩短定位时间。例如原程序很长，但问题只在空列表平均值：

```python
assert summarize([]) == {"count": 0, "average": None}
assert summarize([100]) == {"count": 1, "average": 100.0}
```

这两行分别覆盖空数据与单元素边界。修复后保留小检查，之后重构模块时也能及时发现行为变化。

## ⚠️ 易错点辨析

| 常见误解 | 正确理解 | 修正 |
| --- | --- | --- |
| `import` 只读取函数定义 | 模块顶层语句首次导入时也会执行 | 交互流程放进 `main()` |
| `__name__` 永远是文件名 | 直接运行时是 `"__main__"` | 用入口保护判断 |
| 函数里直接 `input()` 最方便测试 | 固定输入难以注入 | 让函数接收参数并返回结果 |
| traceback 第一行最重要 | 最后一行通常先给异常类型和消息 | 从下向上定位自己的代码 |
| 捕获 `Exception` 就算修复 | 可能只是隐藏逻辑错误 | 先修根因，只捕获可处理异常 |
| 正常样例通过就完成 | 空列表、单元素仍可能失败 | 至少补一个边界检查 |
